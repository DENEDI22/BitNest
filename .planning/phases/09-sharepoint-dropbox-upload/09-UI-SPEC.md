## Component Inventory

Components this phase introduces or extends, with their visual contract:

### New: `upload.html` — Public Upload Page

Structural template: `share.html` (four view-state sections, `.app` wrapper, `.app-header` + `.brand` header, `style.css`).

Four view states (mutually exclusive, toggled via `setVisible()` / `view-hidden` / `view-visible`):

| State ID | When Shown | Visual |
|----------|-----------|--------|
| `#loadingState` | Page load, before metadata fetch completes | `.card.auth-loading-gate` with `.loader.gate-loader` spinner + "Loading…" muted text |
| `#uploadView` | Slot is valid and not full | Context card + dropzone card (see below) |
| `#expiredView` | Token invalid, expired, or revoked (404 from GET metadata) | `.card.error-card` — "Link No Longer Valid" h2, muted body, matches `share.html` expired-view exactly |
| `#slotFullView` | Slot full — 409 from POST upload OR `uploadCount >= maxFileCount` at metadata load | `.card.error-card` — "Upload Slot Full" h2 (distinct heading), "This upload slot is full." body (see Copywriting) |

Header: identical `BitNest Cloud` brand header as `share.html` — `brand-mark` "BN", h1 "BitNest Cloud", subtitle "Secure file sharing". No nav links (public, unauthenticated page).

### `#uploadView` — Context Card + Dropzone Card

**Context card** (`.card`):
- h2: slot label if description is set, otherwise "Upload Files"
- `.share-meta` rows (same border-divided row pattern as `share.html`):
  - "Shared by" / owner username
  - "Created" / slot creation date (formatted: "Mar 20, 2026")
  - "Expires" / expiry datetime (formatted: "Mar 21, 2026 at 3:00 PM")
  - "Description" / slot description (row omitted entirely if description is null)
  - "Remaining" / "X uploads remaining" — shown only if `maxFileCount` is set; omitted if `maxFileCount` is null (unlimited)
- Each row: `.share-meta-label` (muted, 13px) + `.share-meta-value` (text, 13px tabular-nums)

**Dropzone card** (`.card`):
- Reuses `.upload-row` pattern from `style.css` exactly (dashed border, drag-over state, `.file-input-hidden` overlay)
- `.file-picker-title`: "Drop a file here or click to browse"
- `.file-picker-hint`: "One file at a time"
- Progress bar: `.upload-progress` → `.upload-progress-bar-wrap` → `.upload-progress-bar` (accent-to-accent2 gradient), `.upload-progress-text` — all existing CSS classes, no new styles needed
- Inline success message: `.success` class paragraph — "File received." — rendered below the dropzone after successful upload; dropzone resets to idle after 2 seconds
- Inline error message: `.auth-message[data-tone="error"]` pattern — shown below dropzone on unexpected upload failure

### Extended: `links.html` — Upload Slot Creation + Type Badge

**"New upload slot" button:**
- Placed in `.card-header` action area, before the links table — same row as "Active Share Links" heading
- Style: `button` (ghost, default style) — label: "New upload slot"

**Upload slot creation form (inline, beneath the action row):**
- Element: `.admin-form` (reuse existing pattern: `background: rgba(0,0,0,0.2)`, `border: 1px solid var(--cardBorder)`, `border-radius: var(--radius)`, `padding: 18px`) toggled `.view-visible` / hidden
- Layout: `.admin-form-content` with `gap: 14px`
- Fields (top to bottom):
  1. Expiry — label "Expires", preset buttons (1 hr / 24 hrs / 7 days / 30 days) in `.expiry-presets` row + custom datetime input `#uploadSlotCustomExpiry` — identical to download link creation pattern
  2. Description — label "Label (optional)", single-line text input, `placeholder="e.g. Photos from the event"`
  3. File count limit — label "Max files", preset buttons (1 / 5 / 10 / 25) in a flex row + custom number input `#uploadSlotCustomCount`, `min="1"`, `placeholder="custom"`
- Form actions row: "Create slot" (`.primary` button) + "Cancel" (ghost button)
- After creation: inline `.success` message with the generated upload URL in a monospaced read-only input (`.generatedLinkUrl` pattern) + Copy URL button — same post-creation pattern as download links

**Type badge column on links table:**
- New `<th>Type</th>` column — second column (after File Name)
- Each row `<td>`: badge element styled with `.admin-user-role` pattern
  - Download links: text "Download", `background: rgba(58,254,192,0.1)`, `color: var(--accent)`, `border-radius: 4px`, `padding: 4px 8px`, `font-size: 12px`
  - Upload slots: text "Upload", `background: rgba(165,242,31,0.1)`, `color: var(--accent2)`, same size/radius
- File name cell for upload slot rows: show slot description if set, otherwise "—" (em dash) in `color: var(--muted)`

## Interaction States

### upload.html — Dropzone

| State | Visual |
|-------|--------|
| Idle | Dashed border `rgba(255,255,255,0.18)`, background `rgba(0,0,0,0.16)` |
| Hover | Dashed border `rgba(58,254,192,0.35)`, background `rgba(58,254,192,0.04)` |
| Drag-over | Solid border `var(--accent)`, background `rgba(58,254,192,0.08)`, class `.drag-over` |
| Uploading | Class `.uploading` — `pointer-events: none`, `opacity: 0.7`; progress bar animates |
| Success | Dropzone returns to idle; `.success` paragraph "File received." appears below; resets after 2s |
| Error (non-409) | `.auth-message[data-tone="error"]` below dropzone — "Upload failed. Please try again." |
| 409 (slot full) | Transition to `#slotFullView` — do not show inline error |

### links.html — Upload Slot Creation Form

| State | Visual |
|-------|--------|
| Hidden | `.admin-form` without `.view-visible` — `display: none` |
| Open | `.admin-form.view-visible` — `display: block`, slides into view |
| Expiry selected | Selected preset-btn shows `border-color: var(--accent)` (same as download link preset) |
| Count selected | Selected count-preset-btn shows `border-color: var(--accent)` |
| Submitting | "Create slot" button `disabled` + `opacity: 0.55` |
| Created | Form hides; generated link container appears with `.success` heading + URL input + Copy URL button |

### links.html — Type Badge

Type badge cells are display-only; no interactive state.
