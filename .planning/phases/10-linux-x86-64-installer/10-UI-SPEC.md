# Phase 10 — UI Design Contract: Linux x86_64 Installer

> Visual and interaction contract for the Textual TUI installer.
> This phase produces a terminal-based interface, not a web/browser UI.
> Generated by gsd-ui-researcher.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — Textual CSS (tcss) only |
| Preset | not applicable |
| Component library | Textual 8.1.1 (textual.widgets) |
| Icon library | Unicode symbols inline: ✔ ✗ ⏳ ▶ — no external icon library |
| Font | Terminal monospace (inherited from host terminal emulator) |

**Note:** This phase has no web frontend. No shadcn, no React, no browser rendering. The
entire UI is a Textual full-screen TUI. Design tokens below map to Textual CSS properties
(`background`, `color`, `padding`, `margin`, `border`), not CSS custom properties or
Tailwind classes.

---

## Screen Inventory

Five `Screen` subclasses, each mapped to one distinct state:

| Screen Class | Route / Trigger | Back Available |
|---|---|---|
| `MainMenuScreen` | App startup | No (Q to quit) |
| `Step1PrerequisitesScreen` | "Install BitNest" selected from main menu | No (return to main menu via Cancel) |
| `Step2ConfigurationScreen` | Next Step pressed on Step 1 | Yes — pops to Step 1 |
| `Step3InstallingScreen` | Next Step pressed on Step 2 (after validation) | No — non-interactive |
| `Step4DoneScreen` | Step 3 sequence completes (success or failure) | No — non-interactive |
| `UpdateScreen` | "Update BitNest" selected from main menu | Yes — pops to main menu |
| `UninstallScreen` | "Uninstall BitNest" selected from main menu | Yes — pops to main menu |
| `UninstallConfirm2Screen` | First uninstall confirm accepted | Yes — pops to UninstallScreen |

## Spacing Scale

Textual CSS uses integer cell units (columns/rows), not pixels. The following scale maps
the standard 8-point proportions to terminal cell units:

| Token | Cell Value | Equivalent | Usage |
|-------|-----------|------------|-------|
| xs | 1 | ~4px equiv | Icon-to-label gap, inline status indicator padding |
| sm | 2 | ~8px equiv | Input field inner padding, button padding horizontal |
| md | 4 | ~16px equiv | Default widget margin, section internal padding |
| lg | 6 | ~24px equiv | Section separation within a screen |
| xl | 8 | ~32px equiv | Screen-level outer padding (top/left/right) |

Exceptions: Step indicator bar at top uses 1-cell vertical padding to remain compact.
Footer/key-binding bar uses 0 vertical padding (Textual Footer widget default).

## Typography

Terminal monospace font throughout — no font choice is made by the installer. The
following governs text ROLE, not font family. All sizes are relative terminal emphasis
levels.

| Role | Textual Equivalent | Weight / Style | Line Height |
|------|--------------------|---------------|-------------|
| Body | `Label` default | normal (400 equiv) | 1.0 (single line) |
| Label / Field hint | `Label` with `dim` CSS class | dim (subdued) | 1.0 |
| Heading / Step title | `Label` with `bold` markup `[bold]` | bold (700 equiv) | 1.2 (one blank line above) |
| Display / Screen title | `Label` with `bold` + accent color | bold (700 equiv) | 1.2 |

Declared sizes (terminal rows, not px):
- Display title: 1 row tall, bold, accent color
- Section heading: 1 row tall, bold, default foreground
- Body / status lines: 1 row tall, normal weight
- Hint / secondary: 1 row tall, dim

No italic. No underline except for URLs in the success screen (rendered as plain text,
not hyperlink).

## Color

This is a Textual TCSS color contract. All values are Textual CSS named colors or hex.
Dark terminal theme. Source: Claude's Discretion (CONTEXT.md — "Exact ANSI color scheme /
Textual CSS" is explicitly delegated here).

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#1a1a2e` (near-black navy) | App background, screen background |
| Secondary (30%) | `#16213e` (dark navy) | Panel / widget container backgrounds, step indicator bar |
| Accent (10%) | `#0f3460` border + `#e94560` highlight | See accent reserved-for list below |
| Success | `#00b894` (green) | ✔ pass indicators, "All services healthy" line |
| Warning | `#fdcb6e` (amber) | Disk space warning, low-RAM advisory |
| Destructive | `#e17055` (red-orange) | ✗ fail indicators, uninstall second-confirm warning text |
| Foreground | `#dfe6e9` (near-white) | All body text on dark backgrounds |
| Dim foreground | `#636e72` (muted grey) | Hint text, secondary labels, placeholder text |

**Accent (`#e94560` bright red-pink) reserved for:**
- Currently selected main menu item (▶ highlight)
- Active step number in step indicator (e.g. "Step 2/4" — step number only)
- Primary action buttons (Next Step, Install BitNest, Confirm)
- Focus ring on active Input widget

**Destructive (`#e17055`) reserved for:**
- ✗ prerequisite fail status icons
- Uninstall second confirmation warning block ("Delete all data... This cannot be undone.")
- Error messages in Step 3 when a command fails

## Widget Specifications

### Main Menu Screen

```
BitNest Installer
─────────────────────────────────────────
  Install BitNest         ◄ pre-highlighted if no state file
  Update BitNest          ◄ pre-highlighted if state file exists
  Uninstall BitNest

  Q  Quit
```

- `ListView` with three `ListItem` entries
- Selected item rendered with accent background (`#e94560`) and bold label
- Navigator: ↑↓ keys, Enter to select
- Q key binding mapped to `app.exit()`
- No header bar — screen title "BitNest Installer" is a bold Display Label at top

### Step Indicator (persistent, all wizard steps)

```
[ Step 1/4 Prerequisites ]  Step 2/4 Configuration   Step 3/4 Installing   Step 4/4 Done
```

- Horizontal `Label` row at screen top
- Current step number + label in accent color, bold
- Other steps in dim foreground
- Separator: two spaces between steps; no dividing lines
- Height: 1 row + 1-cell vertical padding below

### Step 1 — Prerequisites Screen

Each check rendered as one row:

```
✔  Docker Engine          installed
✔  Docker Compose V2      v2.x.x
✗  Port 5000              in use — change in Step 2
⏳  Port 3000              checking...
✔  Disk space             42 GB free
```

- Status icon column: 3 cells wide, right-padded
- Check name column: 22 cells wide
- Result column: remainder of line
- ✔ rendered in success color (`#00b894`)
- ✗ rendered in destructive color (`#e17055`)
- ⏳ rendered in warning color (`#fdcb6e`) — transient, replaced on completion
- "Docker will be installed automatically" replaces ✗ for missing Docker, rendered in warning color
- Next Step button: accent color, right-aligned, disabled until all checks complete
- Back / Cancel: dim foreground, left-aligned, returns to main menu

### Step 2 — Configuration Screen

Five `Input` widgets stacked vertically, each with a label above:

```
Install directory
[~/bitnest                              ]  ← default shown as placeholder value

API port
[5000    ]

Frontend port
[3000    ]

Admin username  (min 3 characters)
[                                       ]

Admin password  (min 8 characters, hidden)
[••••••••                               ]
```

- `Input` focus ring: accent color border
- Inline validation error: rendered as dim destructive text below the field, one row, only when field is invalid on Next Step press
- Password field: `Input(password=True)` — characters replaced with •
- DB password and JWT key: NOT shown, NOT prompted — auto-generated silently
- Next Step button: accent, right-aligned. Triggers re-validation of all fields + port conflict re-check before advancing.
- Back button: dim foreground, left-aligned, pops to Step 1

### Step 3 — Installing Screen

`RichLog` widget fills available height, streaming output lines:

```
[•] Installing Docker Engine...
    → Running: sudo apt-get install -y docker-ce
    → ...
[✔] Docker Engine installed
[✔] User added to docker group
[✔] Install directory created: /home/user/bitnest
[✔] compose.yaml written
[✔] .env written (chmod 600)
[•] Pulling images...  (spinner animates here)
    → denedi22/bitnest_api:latest
    → denedi22/bitnest_frontend:latest
    → postgres:16
[✔] Images pulled
[✔] Stack started
[•] Waiting for services to become healthy...
    api       [✔] healthy
    db        [✔] healthy
    frontend  [✔] healthy
```

- `[•]` in-progress: warning color (`#fdcb6e`), animated — cycles through `[•]` `[••]` `[•••]` at 500ms intervals
- `[✔]` complete: success color (`#00b894`)
- `[✗]` failed: destructive color (`#e17055`) — followed by error message line
- Indented continuation lines (4 spaces) in dim foreground
- No Back button. No Next Step button — screen auto-advances to Step 4 on completion.
- On failure: show error line in destructive color + "Press Q to quit." at bottom

### Step 4 — Done Screen (Success)

```
✔  All services healthy

   Frontend:  http://localhost:3000
   API:       http://localhost:5000

   Your admin account has been created.
   Username:  alice
   Open your browser to get started.

   Run this installer again to update or uninstall BitNest.
```

- ✔ in success color, bold, 24-cell font equivalent (display-role Label)
- URLs in default foreground (plain text — no hyperlink markup)
- Username displayed; password NOT shown
- Re-run hint in dim foreground, bottom of screen
- "Quit" button: dim foreground, right-aligned. Exits app.

### Update Screen

```
Update BitNest
──────────────────────────────────────
Installed at: /home/user/bitnest
Last installed: 2026-03-26T00:00:00Z

[Update BitNest]  [Back]
```

- Read state from `install.json` to populate installed path and timestamp
- `RichLog` appears below buttons once Update BitNest pressed, streaming compose pull + up output
- Health poll result shown inline after stack restarts
- Back button visible before Update BitNest is pressed; hidden once update begins

### Uninstall Screen (First Confirm)

```
Uninstall BitNest
──────────────────────────────────────
This will stop BitNest and remove the installation.

Install directory: /home/user/bitnest

Continue?

[Continue to Uninstall]  [Back]
```

- "Continue?" line: body weight, default foreground
- `[Continue to Uninstall]` button: accent color
- `[Back]` button: dim foreground, pops to main menu

### Uninstall Second Confirm Screen

```
⚠  Delete all data?
──────────────────────────────────────────────────────────────
  This will permanently delete all files and the database.
  This cannot be undone.

  Directory to be deleted: /home/user/bitnest/data

[Delete Everything]  [Keep My Data]
```

- Entire warning block: destructive color (`#e17055`)
- `[Delete Everything]` button: destructive color background, bold
- `[Keep My Data]` button: dim foreground, pops to UninstallScreen

## Interaction Contract

### Navigation

| Action | Widget | Behavior |
|--------|--------|----------|
| ↑↓ | `ListView` (main menu) | Moves highlight between items |
| Enter | `ListView` | Selects item, pushes next screen |
| Tab / Shift+Tab | `Input` fields (Step 2) | Moves focus between inputs |
| Enter on focused `Input` | Step 2 | Moves focus to next input; on last input triggers Next Step validation |
| Click / Enter on "Next Step" | `Button` | Validates all fields; advances screen or shows inline errors |
| Click / Enter on "Back" | `Button` | `app.pop_screen()` |
| Q | Any screen | Quits app (`app.exit()`) |
| Ctrl+C | Any | Textual default — exits app cleanly |

### Validation Timing

- Prerequisite checks (Step 1): run immediately on screen mount, in `@work` thread worker, results streamed to status lines
- Configuration validation (Step 2): triggered only on Next Step press — never on keystroke (no live validation)
- Port re-check (Step 2 → Step 3): socket.bind() called again on Next Step press using the values currently in the port fields

### Spinner Animation

- Used during: `docker compose pull` (Step 3)
- Implementation: Textual `LoadingIndicator` widget OR manual cycling Label in `@work` worker at 500ms intervals
- Spinner is replaced by ✔ or ✗ line on completion

### Thread Safety

- All `subprocess.run` / `subprocess.Popen` calls run inside Textual `@work` thread workers
- `RichLog.write()` called via `call_from_thread()` for cross-thread UI updates
- `app.exit()` on fatal subprocess failure

## Accessibility Notes

Terminal TUI accessibility is governed by the host terminal emulator and screen reader
integration (e.g. `at-spi2` on Linux). The following are enforced within the installer:

- All status states (pass/fail/pending) conveyed by BOTH symbol (✔ ✗ ⏳) AND text — color is never the only differentiator.
- All destructive actions require two explicit confirmations.
- All input fields have visible labels above them (not placeholder-only).
- Error messages appear as text adjacent to the relevant field — not as modal dialogs.
- Keyboard-only navigation is complete: no action requires a mouse click.
